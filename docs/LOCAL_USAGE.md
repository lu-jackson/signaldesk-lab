# 本機日常使用手冊（真實使用模式）

這份是給「拿 SignalDesk Lab 輔助自己的電子筆記業務」的人。第一次安裝請先看 [GETTING_STARTED](GETTING_STARTED.md)。

## 它做什麼、不做什麼
- **做**：你把在社群上看到的公開貼文貼進來（單則或 CSV），工具判斷是不是在求助、風險高不高，並備好回覆草稿。
- **不做**：不會自動搜尋社群、不會自動留言或私訊。投遞只寫本機模擬；**草稿要你核准後，自己到平台貼上**。
- 判斷是「規則／模板」，不是 LLM；可能誤判。看到分類不對，以你的判斷為準。

## 兩種模式（資料庫是分開的）
| | Demo 模式 | 真實使用模式 |
|---|---|---|
| 啟動 | `python scripts/launcher.py start` | `powershell -ExecutionPolicy Bypass -File scripts\real.ps1` |
| 資料庫 | `data/signaldesk.db` | `data/real.db` |
| 內容 | 120 篇合成貼文、合成留言與點擊 | **只有你匯入的內容** |
| 用途 | 展示、學習 | 日常工作 |

兩個資料庫互不影響；切換模式不會刪任何資料。

## 啟動與停止（真實使用模式）
```powershell
powershell -ExecutionPolicy Bypass -File scripts\real.ps1
```
開啟 http://127.0.0.1:8000 。畫面上方模式列應顯示「資料來源：本機資料庫（手動／CSV 匯入）」。停止：在該視窗按 `Ctrl+C`。
只綁 127.0.0.1，外部連不到；不需要任何金鑰。

## 每天的流程
1. **匯入貼文**（側邊欄「匯入貼文」）：貼單則，或用 CSV 一次最多 50 列。選對應的專案（例如微積分），作者帳號可留空。
2. **看結果**：意圖（seeking＝明確求助）、風險、分類理由。只有「明確求助、相關、無安全疑慮」才會備草稿。
3. **審核草稿**（「草稿審核」）：修改、核准或退回。真實使用模式預設只顯示「待處理」，已處理的不會擋在前面。
4. **複製並自己貼到平台**：核准後按「複製草稿」，需要的話按「開啟原貼文」（有填網址才有），到平台自己貼上回覆。
5. **回來記錄**：按「我已貼到平台」（必須是核准有效的草稿，可附備註）或「略過」（可寫原因）。按錯可「復原記錄」。
   已記錄為「已貼到平台」的草稿會鎖定，不能再修改、拒絕或重新生成（避免記錄和實際貼出的內容對不上）；要改請先復原。
   這只是你的記錄，**工具不會替你送出任何東西**；「模擬送出」是展示用，真實使用模式不顯示。
6. 請不要匯入私訊或含個人資料的內容；作者帳號、網址是選填。

## 品牌事實更新了怎麼辦
程式內的品牌事實（9 本書的價格、頁數等）更新後，**既有資料庫不會自動變**，要手動升級：
```powershell
powershell -ExecutionPolicy Bypass -File scripts\real.ps1 upgrade         # 先預覽差異（品牌內容不會變）
powershell -ExecutionPolicy Bypass -File scripts\real.ps1 upgrade-apply   # 確認後套用
```
套用是「新增一個品牌版本」，舊版與引用舊版的草稿都保留。預覽時會自動補上缺少的專案（只新增、不覆蓋）。
價格或方案以官網為準；官網變動時請先確認再升級。

## 常見問題
| 狀況 | 原因與做法 |
|---|---|
| 按匯入顯示「不允許的 Origin」 | 你用了不是 8000 的網址／埠。請用 http://127.0.0.1:8000 ，或在 `.env` 設 `SIGNALDESK_ORIGINS` |
| 找不到 `backend\.venv` | 還沒安裝，先執行 `python scripts\launcher.py setup` |
| 看不到新的專案或書 | 專案會自動補；品牌事實要用上面的 `upgrade` 升級 |
| 同一則貼文重複匯入 | 只存一份，會標「重複」，不會重複計費 |
| 想用 Live AI（LLM） | 需要你自己的 Anthropic 金鑰與模型，放在 `.env`（不要進 git）；會產生費用，預設關閉。見 TODO 的 C 區 |
