# 案例筆記：可展示／不可聲稱

## 這個專案是什麼
個人學習用的本機「社群商機與互動代理」實驗室：品牌設定 → 搜尋合成貼文 → 意圖／風險分類 → 草稿 → 人工審核 → 模擬送出 → 名單與分析，另有背景工作、事件重播、使用量帳本與可呼叫工具的 AI 助手。全部資料為合成，所有投遞只寫入本機。與任何特定公司的名稱、資料、原始碼或外觀無關。

## 可以展示的（都有實際測試佐證，見 TEST_REPORT）
- 一個垂直流程端到端可運作：搜尋、分類、草稿、核准（綁 hash）、模擬送出，狀態都在 SQLite。
- 「副作用只發生一次」的工程做法：全局去重鍵、idempotency key、事件 `UNIQUE`、帳本 `UNIQUE(operation_id, entry_type)`。
- 失敗語意：可重試／終局失敗／結果不明三者分開處理；worker lease 過期時，有副作用的工作停在 unknown。
- Agent 邊界：工具白名單、參數驗證、回合／工具上限、寫入只能提案且需 UI 確認、外部文字視為不可信資料。
- Demo 與 Live 共用介面、並如實標示：沒有金鑰也能完成全部流程。
- 小型合成資料評估（36 筆）與如何誠實報告（混淆矩陣、零分母處理、失誤列表）。
- 測試：91 個後端測試、4 個瀏覽器 E2E、typecheck/build；測試用臨時 DB 與可凍結時鐘。

## 不可聲稱的
- ❌ 「使用了 LLM／AI 判斷」——Demo 模式是關鍵詞規則與模板；助手是 scripted planner。Live 模式**從未對真實 API 測過**。
- ❌ 任何商業成效：沒有真實使用者、真實社群貼文、成交或轉換；所有點擊與 engagement 為合成或本機自測。
- ❌ 「準確率 94%」——那是 36 筆同作者合成句子的結果，不能一般化。
- ❌ 「已整合 Threads／可自動回覆真實社群」——只有未實測的唯讀 adapter；系統完全沒有真實發送能力。
- ❌ 「可部署上線／多使用者／安全」——單使用者、無登入、僅限 localhost。
- ❌ 與任何現有商用產品的比較或複製；這是從零設計的學習專案。
- ❌ macOS/Linux 已驗證——只在 Windows 11 實測。

## 架構取捨（一句話版）
- 規則放 service 層，API／worker／agent 共用 → 不能繞過審核，但多一層呼叫。
- SQLite＋獨立 worker → 零外部服務、可觀察，但是輪詢與單機。
- 核准綁 hash → 安全但多一次點擊。
- unknown 不自動重試 → 避免重複發送，但需要人工對帳。
- Demo 規則透明但粗糙；Live 彈性高但有成本與不確定性——所以兩者分開、不自動降級。

## 測試結果摘要
後端 91 passed；前端 `tsc --noEmit` 與 `vite build` exit 0；Playwright 4 passed（Edge）；分類 eval 意圖 accuracy 0.944（n=36，僅供學習）。未驗證項目見 KNOWN_LIMITATIONS。
